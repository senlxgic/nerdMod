# Weather (Phase 2D) — the Weather app and the home card

Status: **CI-built, NOT real-hardware verified.** Nothing below has been run on a DSi yet.

## Architecture

```
weather.srldr  (BlocksDS lane: DSWiFi DSi mode + WPA2, Mbed TLS, HTTPS)  ──writes──►  sd:/_nds/nerdMod/cache/weather/weather.ini
dsimenu.srldr  (legacy devkitPro lane, no network code at all)           ──reads───►  the same file
```

* The legacy launcher is not touched by the network stack: it only reads the cache once and never waits for the network. (The
  Phase 2C background-request state machine in the home card only ever saw `UnavailableTransport` and stays that way.)
* `weather/` is built by its own CI job (BlocksDS, `make -C weather`) and the resulting `weather.nds` is packaged as
  `_nds/TWiLightMenu/weather.srldr`. The devkitPro container of the main build is unchanged. The CI asserts that the file is in the artifact.
* The app is DSi-only (unit code 3). It is a normal home tile (registry entry `weather`), shown only when `weather.srldr` exists.

## Network

* Wi-Fi: DSWiFi with `WIFI_ATTEMPT_DSI_MODE`, connecting through the access point stored in the console's firmware settings (no
  password entry in the app; DSi-mode WPA2 as supported by the library).
* HTTPS: Mbed TLS, certificate verification REQUIRED, hostname check (also SNI). The roots are in `source/cacerts.h`
  (generated by `tools/gencerts.py`). Verification is never disabled. If the DSi clock is before 2026-01-01 the request is refused with a
  clock message instead of failing every certificate with a confusing error.
* Every wait has a time limit and a cancel key; the only uninterruptible call is the DNS lookup (bounded by the resolver).
* Messages are specific: no Wi-Fi library, no access point, timeout, clock not set, DNS, TCP, TLS handshake, certificate (expired / not yet
  valid / unknown root / wrong host name), HTTP status, malformed JSON, too large.

## Provider

[Open-Meteo](https://open-meteo.com/): `geocoding-api.open-meteo.com/v1/search` (city search) and `api.open-meteo.com/v1/forecast`
(current conditions, daily high/low, 5-day forecast). No API key; nothing secret is stored. Parsing is strict
(`nmjson.h` + `nmweather.h`): bad JSON, NaN, out-of-range values or unknown weather codes are rejected, never invented.

## App

Top: condition illustration, city, temperature, condition. Bottom: today / tomorrow / next days and the buttons
Change City, Refresh, Units (°C/°F), Auto refresh (on/off, interval 30 min / 1 h / 3 h / 6 h), Network Test, Back.
Change City opens a touch keyboard, queries the geocoder and lists the results (name, region, country) to pick from; the choice stores
name, latitude, longitude, country and timezone. Opening the app refreshes when the data is stale.

## Files

| File | Written by | Content |
|---|---|---|
| `sd:/_nds/nerdMod/weather.ini` | Weather app (and by hand) | `NAME`, `LATITUDE`, `LONGITUDE`, `COUNTRY`, `TIMEZONE`, `UNITS`, `AUTO_REFRESH`, `INTERVAL_MIN` |
| `sd:/_nds/nerdMod/cache/weather/weather.ini` | Weather app | `TEMP_C10`, `CONDITION`, `TIME`, `LOCATION`, `PROVIDER`, `VERSION` + forecast block |

The home card shows temperature, condition and the age ("2H AGO"); stale data is marked, no data shows `--`.

## Tests

`camera/tools/hosttest`: `test_weather` (model, cache, parser), `test_weather_app` (geocoder response, forecast parsing, settings, cache round trip,
stale rules, units), `test_wdraw` (UI drawing helpers), `test_net`.

## Not verified

Everything that touches the radio or the real servers: DSi-mode association, WPA2, DHCP/DNS, the TLS handshake against the bundled roots,
and the real Open-Meteo responses. The Network Test page of the app exists to find out which of these steps fails.
